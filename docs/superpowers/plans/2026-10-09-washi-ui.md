# Washi UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the app the Washi look (cream paper panel, serif, small-caps rules, square controls, one seal red) without changing what it does.

**Architecture:** Rewrite `style.css` on the same page skeleton. `index.html` changes text only (kanji icons, plain-word labels) and `app.js` changes label strings only, so every id, class and handler stays where the code and tests expect it. New tests guard what the redesign could silently break: offline loading, readable contrast, and the panel at phone width.

**Tech Stack:** Plain HTML, CSS and classic scripts; the repo's own test harness (`tests/harness.js`, run by `node tests/run.mjs` in headless Edge or Chrome).

**Spec:** `docs/superpowers/specs/2026-10-09-washi-ui-design.md`

**Visual reference:** `.superpowers/brainstorm/washi-proto/washi.css`, the approved mockup's stylesheet (local only, not in git). The spec wins where they differ.

## Global Constraints

- Layout unchanged: `#panel` 320 px wide beside `#stage`; below 860 px the panel stacks above the stage, `max-height: 46vh`.
- No id, class, `data-` attribute or element is added to or removed from `index.html`; only text inside elements changes.
- `app.js`: only the string literals listed in Task 2 change.
- No network: no web fonts, no `@import`, no `@font-face`, every `url()` relative or `data:`.
- Colours exactly as the spec's table: `--panel #f2ece0`, `--panel-2 #e9e1d0`, `--ink #1b1a17`, `--ink-2 #4a4439`, `--muted #6b6253`, `--rule rgba(27,26,23,.16)`, `--rule-2 rgba(27,26,23,.34)`, `--seal #b3261e`, `--seal-2 #951d16`, `--seal-ink #fbf3e6`, `--moss #4f6b34`, `--ochre #8a6510`, `--rust #a3401a`, `--paper #f8f6f0`; page and stage `#e6dece`.
- Fonts: `--serif: "Iowan Old Style","Palatino Linotype",Palatino,"Book Antiqua",Georgia,serif`; `--mono: ui-monospace,"Cascadia Mono",Consolas,Menlo,monospace`.
- Files never touched: `js/*`, `dist/*`, `examples/*`, `bench/*`, the exported player (`js/export.js`).
- Don't commit `.superpowers/`.

## Review Focus

1. **Labels that change while the app works** (Generate becomes Cancel while generating, Replay becomes Stop or Finishing…, WebM becomes Stop · n%) must show the new words in every state, not just the first. Pinned in Task 2.
2. **Wider serif text at phone width:** the panel must not scroll sideways at 375 px, after painting, with Advanced open. The existing test only checks a 1200 px frame. Pinned in Task 3.
3. **Readable text on cream:** the muted and coloured texts (hints, notes, cost meter in each level, Clear, the warning) must keep 4.5 : 1. A later palette tweak shouldn't be able to drift below that unnoticed. Pinned in Task 3.
4. **Offline:** nothing may be fetched from the network. Pinned in Task 1.
5. **Every element the code looks up must still exist.** The existing smoke test "loads with no errors" fails if `app.js` can't find an element, so the markup task re-runs it. Covered by the suite in Task 2.
